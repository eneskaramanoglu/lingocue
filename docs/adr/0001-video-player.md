# 0001. Video player: libmpv via HanumanInstitute.LibMpv

- Status: accepted (Windows verified; macOS pending manual test). Renderer choice amended by [0002](0002-opengl-video-view-on-windows.md).
- Date: 2026-11-18

## Context

LingoCue needs an embedded video preview in an Avalonia 12 window on Windows (x64) and macOS
(Apple Silicon) that:

1. renders ASS subtitles **exactly** like the final burn-in (FFmpeg's `ass`/`subtitles` filter uses
   libass), including styles, boxes and karaoke `\k` tags — the "preview = output" principle;
2. seeks frame-accurately and steps single frames (subtitle timing work);
3. reloads an external subtitle file quickly when the user edits a cue;
4. reports playback position/duration to the UI.

## Options considered

| Option | Avalonia 12 | Subtitle renderer | Notes |
| --- | --- | --- | --- |
| **libmpv + HanumanInstitute.LibMpv(.Avalonia) 0.10.1** | Built for Avalonia 12 | **libass** (same as FFmpeg burn-in) | MIT, maintained (2026). `MpvView` control: native child window on Windows, OpenGL on macOS, software fallback. Same engine family as Subtitle Edit 5. |
| LibVLCSharp.Avalonia 3.10.2 | Compiled against Avalonia 11.3; binary-compatibility risk | VLC's own subtitle renderer (libass only for some paths) | Preview could differ from burn-in. Larger runtime. |
| FFmpeg frame extraction + Avalonia overlay | n/a | Our own text rendering | No audio sync, no real playback, preview ≠ output. Last-resort fallback only. |

## Spike results (Windows 11, NVIDIA GPU, 2026-11-18)

Test: 1280×720 25 fps clip generated by FFmpeg + a hand-written ASS with Turkish text
(`İstanbul`, `ğ ş ı İ ç ö ü`), a `BorderStyle=3` box style and `\k` karaoke tags.

- Video renders inside the window (Win32 native child view); window resizing and the dark theme are fine.
- ASS renders via libass: outline, shadow, opaque box, karaoke fill, all Turkish glyphs correct.
- Play/pause, `seek absolute+exact` and `frame-step` are frame-accurate: after "+5 s, +1 frame" the
  displayed time (06.880) matched the frame counter burnt into the test video (frame 172 @ 25 fps).
- `time-pos`, `duration`, `pause` property observation drives the UI; mpv events are marshalled to the UI thread.
- `sub-add` of an external ASS works after `file-loaded`; `sub-reload` is the refresh path for edits (M2).
- ffprobe (`MediaProbe`) validates files before playback; missing FFmpeg yields an actionable message.

Not yet verified: macOS rendering (OpenGL view), drag-and-drop over the native video surface on Windows
(the drop target is the top-level window; to be checked manually), audio output (only inferred from playback clock).

## Decision

Use **libmpv through HanumanInstitute.LibMpv + HanumanInstitute.LibMpv.Avalonia 0.10.1**, wrapped
behind `IVideoPlayer` (`LingoCue.App/Playback`) so the engine can be replaced without touching view models.

Avalonia rendering modes: `AngleEgl` → `Software` on Windows, `OpenGl` → `Software` on macOS
(the mpv view needs OpenGL; Avalonia does not use Metal on macOS as a consequence).

mpv options set by the app: `keep-open=yes`, `hr-seek=yes`, `sub-auto=no`, `osd-level=0`,
`input-default-bindings=no`, `hwdec=auto-safe`.

## Native library distribution

| Platform | Source | How it ships |
| --- | --- | --- |
| Windows x64 | [shinchiro/mpv-winbuild-cmake](https://github.com/shinchiro/mpv-winbuild-cmake) release `20261111`, asset `mpv-dev-x86_64-20261111-git-bcde6b93cc.7z`, SHA256 `273c079b11ea5575822f972756f4c9a71149a5c10130353abeb8586738938452` | `build/fetch-libmpv.ps1` downloads and verifies it on first build; `libmpv-2.dll` (≈116 MB, FFmpeg statically linked) is copied next to the exe. Never committed. |
| macOS arm64 (dev) | Homebrew `mpv` | `brew install mpv`; the library resolves `/opt/homebrew/lib/libmpv.2.dylib`. |
| macOS arm64 (release) | Homebrew `mpv` on the CI runner | `build/macos/bundle-libmpv.sh` copies libmpv and every non-system dependency into `LingoCue.app/Contents/Frameworks` with `@loader_path` install names (dylibbundler) and fails if any Homebrew path remains. |

To upgrade the Windows build, change release/asset/SHA256 in `build/fetch-libmpv.ps1` together and
note it here.

## Consequences

- Package size grows (Windows +116 MB unpacked; macOS similar with Homebrew dylibs). Trimming is an M9 topic.
- Licensing: these libmpv/FFmpeg builds include GPL components. Fine for this MIT, open-source,
  personal-use project; a closed-source distribution would need LGPL builds.
- The Windows video surface is a native child window: Avalonia controls cannot be drawn on top of the
  video (airspace). Subtitles are drawn by mpv itself, so this is acceptable; banners/overlays are
  placed outside the video area.
- If macOS testing fails, fall back to `VideoRenderer.Software` on macOS before considering LibVLCSharp.
